# Asset licences

## Summary

There are no imported assets. Every mesh, colour, shader and icon in this
project is generated by code in this repository or written by hand in it.
There is no texture file, no audio file, no model file and no font file in
the APK beyond what the Android framework itself provides.

---

## Code

| Component | Origin | Licence |
|---|---|---|
| `core/` — maths, world format, streaming, all five physics models | Written for this project | Same as the repository |
| `android/` — renderer, GLSL, HUD, touch controls | Written for this project | Same as the repository |
| `tools/` — the four-stage data pipeline and the verifier | Written for this project | Same as the repository |
| `tools/androidstub/` — a minimal framework surface for offline type-checking | Written for this project; never on the Gradle classpath, never in the APK | Same as the repository |

No third-party Java or Kotlin library is bundled. The only build-time
dependencies are the Android Gradle Plugin and JUnit 5, neither of which
contributes code to the shipped APK beyond the standard Android framework.

## Geometry

| Asset | How it is made |
|---|---|
| Terrain mesh | Generated at runtime by `ChunkMesher` from the Copernicus height field |
| Buildings | Extruded at runtime from OpenStreetMap footprints |
| Roads | Ribbons generated from OSM centrelines and width tags |
| Sea surface | A procedural grid displaced in the vertex shader by the same four-wave sum the buoyancy solver uses |
| Ambient vehicle | `Meshes.genericCar()` — eleven axis-aligned boxes, every dimension a literal in that file |
| Sky | A gradient across one full-screen triangle |

The map-derived geometry is covered by the ODbL; see `DATA_SOURCES.md`.

### On the vehicles specifically

The brief rules out branded vehicles, and the ambient car is accordingly a
generic three-box saloon, 4.1 m long and 1.72 m wide, with no badge, no grille
pattern, no wheel design and no livery. Its proportions are those of a
small car in general, not of any particular model. The ten body colours are
plain RGB triples chosen to look like ordinary traffic.

The five player vehicles are described by their physical parameters — mass,
inertia tensor, wing area, metacentric height, rotor radius — not by a
likeness. Those parameters are drawn from the published characteristics of
*classes* of vehicle, which are facts rather than designs: a 1,340 kg
hatchback, a 34 tonne harbour ferry, a 2,450 kg light helicopter, a 1,950 kg
light twin. No manufacturer is named anywhere in the code or the UI.

## Icon

`res/drawable/ic_launcher_foreground.xml` is a hand-written vector: a skyline
of plain rectangles above two curved bands for the water. It is not a trace of
any photograph, logo or landmark, and it deliberately avoids resembling any
specific building.

---

## Text and typography

All UI text is in `res/values/strings.xml` and was written for this project.
Type is rendered with the Android system font through `android.graphics.Paint`;
no font file is bundled.

---

## Audio

There is none. No music, no engine samples, no ambience. This is listed as a
limitation in `DELIVERY.md` rather than presented as a choice.

---

## Representation

Dharavi and the other informal settlements that the map data describes are
rendered exactly as every other residential area is: real OSM footprints,
extruded to the same height model, with the same materials. There is no
separate "slum" asset class, no distinguishing colour, and no visual
commentary of any kind. They are part of the city because they are part of the
city.

Airports, ports, military and government areas are included only at the level
of detail that is already public in OpenStreetMap: the outline of the land
use, the public road network around it, and building footprints. No runway
markings, no apron layouts, no security infrastructure, no interior detail,
nothing operationally sensitive.
